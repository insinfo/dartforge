#### E.2.2 `computeType`, `computeTypeParamOrArg`, `computeVariablePatternType`

Nenhuma das três mexe na lista de tokens: só olham adiante e devolvem um `TypeInfo`/
`TypeParamOrArgInfo`, que depois é executado por `parseType`/`ensureType*`/`parseArguments`/
`parseVariables` (aí sim com relatos e reescrita).

**Auxiliares.**
- `isValidNonRecordTypeReference(t)` (`fe:parser/type_info.dart:139`): `IDENTIFIER`; ou palavra
  pseudo; ou embutida **seguida de `.`**; ou `dynamic`, `Function`, `void`.
- `isPossibleRecordType(t)` (`:133`): `(` cujo `endGroup` existe e não é sintético.
- `isGeneralizedFunctionType(t)` (`:127`): `Function` seguido de `<` ou `(`.
- `looksLikeName(t)` (`fe:parser/type_info_impl.dart:486`): `IDENTIFIER`, `this`, `super`, ou
  `t.isIdentifier` (pseudo/embutida) — exceto `typedef` seguido de identificador.
  Palavra reservada **nunca** parece nome.
- `looksLikeNameOrEndOfBlock(t)` (`:497`): `looksLikeName`, EOF ou `}`.
- `looksLikeTypeParamOrArg(inDeclaration, t)` (`:509`): `inDeclaration` e `t` é `IDENTIFIER` seguido
  de `IDENTIFIER`, `,` ou fecho (`isCloser`: `> >> >= >>> >>= >>>=`, `:1665`).

`Complex.computeRest(token, required)` (`type_info_impl.dart:1046`): engole um `?`, depois repete
enquanto vier `Function`: parâmetros de tipo (`computeTypeParamOrArg(…, inDeclaration: true)`), exige
`(` com `endGroup`; com `!required`, depois do `)` (e de um `?`) tem de vir identificador, `this` ou
`super` — senão para ("`Function` usado como nome de função"). Cada volta registra o `Function` em
`typeVariableStarters`, fixa `gftHasReturnType` e avança `end`. `computeNoTypeGFT`/`…VoidGFT`/
`…IdentifierGFT` devolvem `noType`/`simpleType` (`required`), `voidType`, `simpleType` quando
nenhuma volta vale (`:720-931`).

`Complex.computeRecordType(required)` (`:738`): `_checkIfRecordTypeParenthesisAreRecovered` (`:840`)
marca `recovered` se algum campo dá tipo recuperado, se um campo nomeado não tem nome, se falta
vírgula/fecho, se há um único posicional sem vírgula, ou se o grupo não acaba no `endGroup`. Com
`!required` só é tipo se depois do `)` (e `?`) vier: identificador seguido de `; = < ( , ) in } : ]`
(ou `get`/`set` + nome seguido também de `=> { async sync`; ou `operator` + operador); ou
`this.`/`super.`; ou, sem `recovered`, um de `, > >> >>= >>> >>>=` (record como argumento de tipo).

**Chamadas e seus parâmetros** (`parser_impl.dart`): topo `:3522` e membro `:4593` — `(false,
inDeclaration: true)`; comando `:8115` — `(false)`; parâmetro `:2023` — `(inFunctionType, false,
acceptKeyword: true)`, e de novo com `required: true` se o resultado foi `noType` e segue `.` ou
`id .` (`:2031-2038`); `typedef` `:1392` — `(false)`; depois de `is`/`as` `:7855` — `(true)`;
argumento/limite de tipo — `(true, inDeclaration)`.

**`computeVariablePatternType(token, [required = false])`** (`type_info.dart:357`): `computeType`;
se o tipo consumiu algo e o token seguinte é identificador `as` ou `when`, devolve `noType` (o
"tipo" é o próprio padrão; `as`/`when` abrem cast/guarda).

**`computeTypeParamOrArg(token, [inDeclaration = false, allowsVariance = false])`** (`:384`):

```

```

`skip(token)` devolve `skipEnd`: o `>` real, a primeira metade de um `>>`/`>=`/`>>>`… partido **sem**
alterar a cadeia (`splitCloser`, `:1694`; as cópias de `fe:parser/util.dart:156-225` têm o 2º token
em `charOffset + 1`), ou um `>` sintético fora da cadeia (`syntheticGt`, `util.dart:261`, offset do
token seguinte). `C<>` em expressão passa: `next == start`, `>` é fecho, `typeArgumentCount = 0`,
`recovered = false`. `computeMethodTypeArguments` (`type_info.dart:430`) só aceita o grupo se
`!recovered` e o token depois dele é `( . == != ) ] } ; : ,` ou EOF (`mayFollowTypeArgs`, `:452`).

| objeto | método | relato / efeito |
|---|---|---|
| `NoType` | `ensureTypeNotVoid`/`ensureTypeOrVoid` (`type_info_impl.dart:116`) | `EXPECTED_TYPE_NAME` em `token.next` + identificador sintético antes dele; segue como `simpleType` |
| `VoidType` | `ensureTypeNotVoid` (`:429`) | `InvalidVoid` → `EXPECTED_TYPE_NAME` no `void`, que vira nome de tipo |
| `VoidType` | `parseType` (`:444`) | `void<…>`: `VOID_WITH_TYPE_ARGUMENTS` no `<`, argumentos lidos |
| `ComplexTypeInfo` | `parseType` (`:611`) | começa em `.`: `insertSyntheticIdentifier(token, prefixedTypeReference)` → `EXPECTED_TYPE_NAME` no `.`; nome pelo contexto `typeReference` (ou `prefixedTypeReference` + `typeReferenceContinuation` quando há `.`): embutida → `BUILT_IN_IDENTIFIER_AS_TYPE`, `var` → `VAR_AS_TYPE_NAME`; o `?` só é consumido se faz parte do tipo; cada `Function` → `parseFormalParametersRequiredOpt(GeneralizedFunctionType)` |
| `SimpleTypeArgument1GtGt`/`GtEq` | `parseEndGroup` (`:1219`, `:1249`) | reescreve `>>`/`>=` em dois tokens na cadeia; sem relato |

`parseUnexpectedEnd(token, isArguments, parser)` (`:1531-1637`) — o `>` que falta:

```
next = token.next
relatado = token.isSynthetic || (next.isSynthetic && !next.isEof)
relatar(): se !relatado: EXPECTED_TOKEN '>' (ExpectedAfterButGot) em TOKEN (o último consumido); relatado = true
if next == `extends`: relatar(); token = next; se parseCloser(token): return token
if (há tipo válido depois do extends) || next ∈ {dynamic, void, Function}:
    ti = computeType(token, true); se != noType: relatar(); lê o tipo com ouvinte nulo; se parseCloser: return
tp = computeTypeParamOrArg(token, inDeclaration)
se tp != noTypeParamOrArg: relatar(); lê o grupo com ouvinte nulo; se parseCloser: return
if next == `(` com endGroup: relatar(); token = next.endGroup; se parseCloser: return
relatar()
if parseCloser(next): return next
se start.endGroup != null: avança token até token.next == endGroup (pula o que houver, sem relato)
senão: liga um `>` sintético (offset de next) depois de token
```

Posição do `EXPECTED_TOKEN '>'`: sempre o **último token consumido da lista** (`List<int x` → `int`;
`class A<T` + EOF → `T`; `class A<T extends List<int> {}` → o `>`), nunca o token onde o `>` deveria
estar. Se o nome anterior já era sintético (`class A<class> {}`), nada é relatado e `class` é
pulado em silêncio até o `>` casado pelo scanner.
