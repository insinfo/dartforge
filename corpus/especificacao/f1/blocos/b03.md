#### F.R4-1.3 `NamedTypeResolver` (`analyzer/lib/src/dart/resolver/named_type_resolver.dart`)

Fase: `ResolutionVisitor` (antes da inferência). Um `NamedType` tem no máximo **um** qualificador
(`importPrefix`) e o nome (`name2`); `A.b.c` em criação é `ConstructorName(type: A.b, name: c)`.

```
visitNamedType(node)                                   // resolution_visitor.dart:1096-1105
  node.typeArguments?.accept(this)                     // os argumentos são resolvidos ANTES da cabeça
  resolver.nameScope = _nameScope; resolver.resolve(node)
  rewriteResult != null → visita o ConstructorName reescrito

resolve(node)                                          // :84-134
  com qualificador `P.N`:
    pe = nameScope.lookup(P).getter                    // cadeia do ResolutionVisitor (F.R4-1.1)
    pe == null                  → _resolveToElement(node, null)
    pe é Interface ou TypeAlias → _rewriteToConstructorName
    pe é PrefixElement          → _resolveToElement(node, pe.scope.lookup(N).getter)
    senão                       → PREFIX_SHADOWED_BY_LOCAL_DECLARATION no token P [P]; tipo InvalidType
  sem qualificador:
    N == 'void' → VoidType
    senão       → _resolveToElement(node, nameScope.lookup(N).getter)

_resolveToElement(node, el)                            // :304-325
  el == null → InvalidType; se !shouldIgnoreUndefinedNamedType(node) → reportNullOrNonTypeElement(node, null)
  el é MultiplyDefinedElement → InvalidType, sem relato aqui (AMBIGUOUS_IMPORT sai no ErrorVerifier)
  senão → _instantiateElement(node, el), depois _verifyNullability

_rewriteToConstructorName                              // :330-382  (P é classe ou alias)
  pai é ConstructorName sem nome (`new A.foo()`, `= A.foo`): vira tipo `A` + construtor `foo`;
     se havia `<…>` depois de `foo` → WRONG_NUMBER_OF_TYPE_ARGUMENTS_CONSTRUCTOR nos argumentos [A, foo]
  senão, em criação (`new A.foo.x()`) → reportNewWithNonType
  senão → NOT_A_TYPE em [P.offset, N.end), argumento 'P.N'       // ANTES de qualquer contexto

_instantiateElement(node, el)                          // :203-289
  Interface → com <args>: _buildTypeArguments(nº de parâmetros); sem: mixin já calculado do `with`,
              inferência do redirecionamento, ou instantiateInterfaceToBounds
  TypeAlias → idem, depois _verifyTypeAliasForContext
  qualquer outro elemento em criação (pai ConstructorName de InstanceCreationExpression) → reportNewWithNonType
  dynamic | Never | TypeParameter → o tipo; com <args>: _buildTypeArguments(0)
  senão → reportNullOrNonTypeElement(node, el)

_buildTypeArguments (:137-160): nº de argumentos != nº de parâmetros → WRONG_NUMBER_OF_TYPE_ARGUMENTS
   no NamedType INTEIRO (com `<…>` e `?`) [N, parâmetros, argumentos]; os argumentos viram InvalidType
_verifyTypeAliasForContext (:420-483): alias que expande para parâmetro de tipo em criação, redirecionamento
   ou cláusula → *_TYPE_ALIAS_EXPANDS_TO_TYPE_PARAMETER; alias de tipo não interface em criação → reportNewWithNonType
_verifyNullability (:388-418): `?` em cláusula → NULLABLE_TYPE_IN_{EXTENDS,IMPLEMENTS,ON,WITH}_CLAUSE
```

método, parâmetro, local, extensão, prefixo usado como nome):

Faixa (`_getErrorRange`, `:653-666`): de `name2` ao fim de `name2`; começa no qualificador quando ele
existe e (a faixa é "completa" ou o qualificador **não** resolveu para `PrefixElement`). Nunca inclui
`<…>` nem `?`. Logo `new p.Undef()` marca só `Undef`; `new A.foo.x()` marca `A.foo`.

Cláusulas (linha 9): quem relata é `ResolutionVisitor._resolveType` (`resolution_visitor.dart:1652-1724`),
depois de `visitNamedType`: `hasErrorReported` → nada; elemento do tipo é classe → ok; mixin em
`implements`/`on`/`with` → ok; `shouldIgnoreUndefinedNamedType` → nada; senão, por cláusula:
superclasse de `class X = S with M` → `MIXIN_WITH_NON_CLASS_SUPERCLASS`; `extends` →
`EXTENDS_NON_CLASS` (ou `MIXIN_WITH_NON_CLASS_SUPERCLASS` se a classe tem `with`); `implements` →
`IMPLEMENTS_NON_CLASS`; `on` de mixin → `MIXIN_SUPER_CLASS_CONSTRAINT_NON_INTERFACE`; `with` →
`MIXIN_OF_NON_CLASS`; faixa do qualificador ao fim do nome, sem argumentos. Como `MixinOnClause`
não está na linha 9, o `on` de mixin dá **dois** diagnósticos (`undefined_class` ou `not_a_type`,
mais o da cláusula). `PREFIX_SHADOWED…` e `NOT_A_TYPE 'P.N'` também se somam ao da cláusula.

`shouldIgnoreUndefined(prefix, name)` (`analyzer/lib/src/dart/element/element.dart:1186-1221`): para
cada import da unidade e das envolventes com o **mesmo prefixo** (nulo = sem prefixo) e biblioteca
importada inexistente ou sintética: com prefixo e sem nenhum `show` → ignora; algum `show` cita o
nome → ignora. Sem prefixo e nome começando por `_$`: ignora se alguma diretiva `part` **desta
unidade** aponta para arquivo gerado (`file_paths.isGenerated`) que não existe.
