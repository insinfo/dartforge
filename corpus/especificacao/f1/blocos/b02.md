#### F.R4-1.2 Escopo da biblioteca e de importação (`LibraryFragmentScope`, `PrefixScope`)

No 3.6.2 as classes são `LibraryFragmentScope` (uma por unidade; a de uma parte tem como `parent` a
do arquivo que a inclui) e `PrefixScope`; não existe `LibraryOrAugmentationScope` nesta versão.

```
LibraryFragmentScope.lookup(id)                                   // scope.dart:423-441
  1. _lookupLibrary(id)   // :485-496  declarações da biblioteca INTEIRA (todas as unidades)
       getter ou setter declarado → devolve o par; fim
  2. _lookupCombined(id)  // :464-483
       a. _prefixElements[id] → (getter: PrefixElement, setter: null)   // :466-472
          ('_' só é prefixo sem wildcard_variables, :498-504)
       b. noPrefixScope.lookup(id) com getter ou setter → devolve       // :476-479
       c. parent?._lookupCombined(id)                                   // :482  (parte → arquivo que a inclui)
  3. (null, null)
```

Precedência: **declaração da biblioteca > prefixo > nome importado sem prefixo > imports do
arquivo envolvente**. Não há erro na construção; o conflito de nome de prefixo com declaração é
`PREFIX_COLLIDES_WITH_TOP_LEVEL_MEMBER` (outro verificador), e a declaração esconde o prefixo.

`LibraryDeclarations` (`scope.dart:282-333`): por unidade, nesta ordem, acessadores (getters e
setters de variáveis e os explícitos; sem os aumentados), funções, enums, extensões (com nome),
extension types, typedefs, mixins, classes; a primeira ocorrência de um nome vence (`??=`), então
entre homônimos de espécies diferentes vence a espécie que vem antes nessa lista. Só na própria
`dart:core` entram `dynamic` e `Never` (`:288-292`).

`PrefixScope` (um para "sem prefixo" e um por `PrefixElement`; construtor `scope.dart:532-563`):

```
para cada import da UNIDADE, na ordem das diretivas:
  entra só se a URI resolveu para biblioteca (DirectiveUriWithLibraryImpl) e o prefixo é o deste escopo
  para cada exportedReference da biblioteca importada:      // o namespace de exportação dela
     se combinators.allows(nome) e _shouldAdd(...):          // todo show contém e nenhum hide contém; 'x=' vale 'x' (summary2/combinator.dart:20-36)
        setter → _addTo(_setters) ; senão → _addTo(_getters) (extensão também em _extensions)   // :615-632
  import deferred → _deferredLibrary ??= biblioteca          // :558-560
_addTo (:634-669): chave = element.displayName; vazio → grava; mesmo elemento → nada; outro → _merge
_merge (:671-692): um é do SDK e o outro não → fica o que NÃO é do SDK (em qualquer ordem, sem erro)
                   senão → MultiplyDefinedElementImpl(nome, conjunto achatado dos conflitantes)
_isSdkElement (:721-729): dynamic/Never → sim; MultiplyDefined → não; senão element.library.isInSdk
lookup (:576-608): deferred e id == 'loadLibrary' → (loadLibraryFunction, null)
                   getter/setter deste escopo; senão parent (prefixo homônimo do arquivo envolvente;
                   prefixo deferred não tem parent, :447-462); senão (null, null)
```

- **`dart:core` implícito**: é um import sem prefixo acrescentado **por último** à lista da
  biblioteca quando nenhuma diretiva `import` do arquivo da biblioteca tem a URI `dart:core`
  (`analyzer/lib/src/dart/analysis/file_state.dart:288-303`, `hasDartCoreImport` em `:1050-1052`).
  Qualquer import explícito de `dart:core` — com prefixo, `show` ou `hide` — retira o implícito.
- **`dynamic` e `Never`** são referências exportadas de `dart:core`
  (`analyzer/lib/src/summary2/library_builder.dart:1311-1320`): obedecem a prefixo e combinadores como
  qualquer nome. `void` não passa por escopo (`named_type_resolver.dart:126-129`).
- **`Record`** de `dart:core` não entra no escopo de biblioteca sem o recurso `records`
  (`_shouldAdd`, `scope.dart:694-708`).
- Getter e setter são mapas independentes: `get x` de uma biblioteca e `set x` de outra não conflitam.
- O mesmo elemento por dois caminhos (import direto e reexport) não conflita (`existing == element`, `:658-663`).
- O `MultiplyDefinedElement` é guardado no mapa e só vira diagnóstico **no uso** (`AMBIGUOUS_IMPORT`,
  pelo `ErrorVerifier`; ver o código).
- **Exportação**: o namespace de exportação é montado pelo ligador; num conflito entre dois exports o
  **primeiro** fica e o segundo é descartado em silêncio (`ExportScope.export`,
  `analyzer/lib/src/summary2/export.dart:118-139`; a declaração local sempre entra, `:112-116`). Quem
  importa a biblioteca não vê ambiguidade; o erro `AMBIGUOUS_EXPORT` sai só na diretiva.
- Extensões acessíveis: declaradas na biblioteca + as de todos os `PrefixScope` (sem e com prefixo) +
  as do arquivo envolvente (`accessibleExtensions`, `scope.dart:384-392`).

Exemplo `t05.dart` (prefixo vence nome importado homônimo):
```dart
import 'dart:math' as max;
import 'dart:math';
void f() {
  max;
  max(1, 2);
  max.max(1, 2);
  min(1, 2);
}
```

- `prefix_identifier_not_followed_by_dot | 67+3 | 5:3 | The name 'max' refers to an import prefix, so it must be followed by '.'.`

- `not_a_type | 86+8 | 6:1 | q.Future isn't a type.`
