Consequências conferidas no vivo: só há `where` quando **dois argumentos-tipo do mesmo relato** têm
o mesmo texto e elementos diferentes de mesmo nome (p04 `C`×`C`, `List<C>`×`List<C>`,
`void Function(C)`×`void Function(C)`); o mesmo elemento dos dois lados não entra (`G<C>`: só `C`
é citado, p04); um argumento-tipo sozinho nunca ganha `where` (p04 `'C'` × `'int'`; p11
`undefined_method … for the type 'C'` — ali `{1}` é `String`); records não são percorridos (p12
`'(C,)'` × `'(C,)'` sem `where`); o alias não esconde os elementos (p12 `P<C>`: percorre o
`Map<C, C>` real); `Map<C, C>` com os dois `C` diferentes lista os dois, na ordem dos argumentos de
tipo (p12). O caminho é `source.fullName` (no Windows, `E:\…\a.dart`); o registro do corpus o
normaliza para `<raiz>/…` (`crates/paridade/src/oraculo.rs:120` `sem_raiz`).

Parâmetros de função (`_writeFormalParameters(forElement: false)`, `:405-462`, e
`_writeWithoutDelimiters`, `:531-553`):

```
"(" ; grupo = nenhum
para cada parâmetro i (na ordem de FunctionType.parameters):
   se i != 0: ", "
```

- Posicionais: só o tipo. Nomeados: `tipo nome`, com `required ` na frente. **Sem** `covariant`, **sem**
  valor padrão (o padrão só sai com `forElement: true`, `:546-552`) (p06).
- Os nomeados saem **ordenados por nome** (`String.compareTo`): o `FunctionTypeImpl` reordena na
  construção (`type.dart:120-160`, `sortedNamedParameters.sort`, `:157`) — p06: declarado
  `{covariant int z = 0, required String a}` → `{required String a, int z}`; declarado
  `{int zz, required int aa, int? mm}` → `{required int aa, int? mm, int zz}`.
- Formais (`_writeTypeParameters`, `:502-513` → `writeTypeParameter`, `:322-338`): `<T, S extends B>`;
  o `extends` sai quando `element.bound != null` (limite escrito) (p01 `T Function<T extends num>(T)`);
  variância explícita (`in`/`out`/`inout`) vem antes do nome quando não é a legada.

**1.3 Alias** (`_maybeWriteTypeAlias`, `:379-389`): com `preferTypeAlias` e `type.alias != null`,
escreve `alias.element.name` + `<alias.typeArguments>` + sufixo do **tipo** e não desce no tipo real.
Vale em qualquer profundidade (o `_writeType` dos argumentos volta ao mesmo construtor): `F<int>`,
`L?`, `List<F<String>>`, `A<String>` (alias que nem usa o parâmetro), `R` (alias de record), `F<int>?`
(p03). Sem `preferTypeAlias` (elemento convertido por `_convertElements`, ou `getDisplayString()`
chamado pelo emissor) o alias é expandido.

**1.4 Renomeação de formais** (`_uniqueTypeParameters`, `:555-608`), só em tipo de função com formais:

```
referidos = {}                                           # elementos de parâmetros de tipo
coleta(t):                                               # :562-578
   TypeParameterType -> referidos.add(t.element)
   FunctionType      -> para cada formal f: coleta(f.bound); para cada parâmetro: coleta(tipo); coleta(retorno)
   InterfaceType     -> para cada argumento de tipo: coleta(arg)
   (RecordType e os demais: nada)
coleta(tipo) ; referidos -= tipo.typeFormals             # :580-581
evitar = { displayName de cada referido }                # :583-586
para cada formal f de tipo.typeFormals, na ordem:        # :588-605
   nome = f.name
   para contador = 0, 1, 2…: enquanto !evitar.add(nome):
        nome = f.name + subscrito(contador)              # dígitos U+2080..U+2089: T₀, T₁, … T₁₀
   novo formal (nome, mesmo bound)
devolve replaceTypeParameters(tipo, novos)               # :607
```
- `referidos` inclui os formais das funções **aninhadas** (a coleta entra na função interna e acha os
  `T` dela; só os formais da função de fora são retirados). Por isso `void Function<T>(T, void
  Function<T>(T))` sai `void Function<T₀>(T₀, void Function<T>(T))` (p01) e `void
  Function<T>(List<T> Function<T>(T))` sai `void Function<T₀>(List<T> Function<T>(T))` (p13), mesmo
  sem conflito real. A função interna é escrita depois, pelo mesmo método, com o seu próprio cálculo.
- Conflito real, por substituição: `void Function<S>(S, T)` com `T := S` do chamador sai `void
  Function<S₀>(S₀, S)` (p01).
- `evitar.add` também registra o nome final de cada formal: dois formais que acabem com o mesmo nome
  recebem subscritos sucessivos.
- Com alias preferido o método nem roda (`:186-188` retorna antes).

Há **dois formatadores de tipo** e nenhuma etapa comum de argumentos:

1. `TypeTable::formatar` (`crates/types/src/table.rs:422-580`), público como `format` (`:413`, com
   alias) e `format_sem_alias` (`:418`). No disco (trabalho não commitado, posterior ao placar r7):
   - decorações `Exibicao` (`:150-159`: `Alias { typedef, args }`, `NeverAnulavel`, `Invalido`), lidas

     reproduzem 1.4 (inclusive a coleta dentro de funções aninhadas e os subscritos por dígito);
     posicionais, `[opcionais]`, `{nomeados}` com `required`; formais com `extends` quando o limite é
     explícito ou não é `Object?`/`dynamic` (`:497-517`); sufixo `?` sem parênteses;
   - **nomeados de função na ordem armazenada** (`:486-493`), e a tabela os guarda ordenados por
