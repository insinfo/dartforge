#### E.2.1 `IdentifierContext`: todos os contextos e a recuperação de cada um

**Entrada comum** (`fe:parser/parser_impl.dart`):

`rewriter.insertSyntheticIdentifier(t)` cria `SyntheticStringToken(IDENTIFIER, '', offset =
t.next.charOffset, length 0)` e o liga **depois de `t`**. `recoveryTemplate` é `ExpectedIdentifier`
em todos os contextos, salvo `typeReference` e `prefixedTypeReference` (`ExpectedType`,
`fe:parser/identifier_context_impl.dart:1198`, `:1208`).

**Os quatro desfechos** (`id` = `token.next`, o token que deveria ser o nome):

| sigla | relato | o que acontece com `id` | nome devolvido |
|---|---|---|---|
| **S** (sintético antes) | `MISSING_IDENTIFIER` em `id` (offset/length de `id`; EOF → length 0) | **não é consumido** | sintético inserido entre `token` e `id`, offset de `id`, length 0 |
| **C** (consome) | `MISSING_IDENTIFIER` em `id` | é pulado (fica na cadeia, sem evento) | sintético inserido **depois** de `id`, offset de `id.next` |
| **K** (palavra como nome) | `EXPECTED_IDENTIFIER_BUT_GOT_KEYWORD` em `id`, argumento = lexema | consumido como o nome | o próprio `id` |
| **B** (embutido) | `BuiltInIdentifierInDeclaration` do parser — o analyzer **descarta** (E.2.0); quem relata é o `ErrorVerifier` (`BUILT_IN_IDENTIFIER_AS_TYPE_NAME`/`_TYPEDEF_NAME`/`_PREFIX_NAME`/`_TYPE_PARAMETER_NAME`/`_EXTENSION_NAME`), para toda palavra-chave não pseudo, inclusive reservada (`error_verifier.dart:2323`) | consumido como o nome | o próprio `id` |

**Molde** usado por quase todos (variações na tabela):

```
ctx.ensureIdentifier(token, parser):

  if ACEITA(id): [checkAsyncAwaitYieldAsIdentifier(id)]; return id

  elif !id.isKeywordOrIdentifier: C          // "when in doubt, consume the token to ensure we make progress"

```

**Contexto de expressão** (`ExpressionIdentifierContext.ensureIdentifier`, `:324-377`):

```
id = token.next
if id.isIdentifier:
    if id == `await` && id.next.isIdentifier: UNEXPECTED_TOKEN em `await`; return id.next
    checkAsyncAwaitYieldAsIdentifier(id); return id
relatar_em = id
if token == `$` && id.isKeyword && id.next.kind == STRING_TOKEN:      // "$class", "$is", "$super"
    K; return id
if !looksLikeStatementStart(id):
    if id.isKeywordOrIdentifier:
        if isContinuation || id ∉ {as, is}: K; return id
        // `as`/`is` fora de continuação: cai para o sintético
    elif !id.isOperator && id ∉ {. , ( ) [ ] { } ? : ;} && !id.isEof:
        token = id                                                    // consome o token estranho (`=>`, `...`…)
MISSING_IDENTIFIER em relatar_em
return rewriter.insertSyntheticIdentifier(token)
```

Consequências: palavra que abre comando (`if`, `return`, `var`, `void`…, `@`, EOF) e operadores nunca
são consumidos; `"$this"` não passa por aqui (`parseIdentifierExpression`, `:7584`, trata `this`).
Quando K acontece em expressão, o AST fica com um `SimpleIdentifier` de token palavra-chave: depois
vêm `undefined_identifier` (resolução) e, se a expressão é o comando inteiro,
`MISSING_STATEMENT` do AstBuilder (`an:fasta/ast_builder.dart:4243-4248`: `SimpleIdentifier` cujo
`token.keyword` não é embutido nem pseudo).

**Onde a palavra reservada nem chega ao contexto** (decisão antes do `ensureIdentifier`):
- *Topo* (`parseTopLevelMemberImpl`, `:3540-3553`): `typeInfo == noType`, sem `var/final/const`,
  `isReservedKeyword(next.next)` e `indicatesMethodOrField(next.next.next)` (`; = ( { => <`, `:4441`) →
  recalcula o tipo com `required = true` e marca `nameIsRecovered` → K pelo caminho "recuperado".
  Vale para `int class = 10;` e `int class() => 1;`. **Não** vale para `void class() {}`: `void` já é
  tipo (`voidType`), o nome vai ao contexto sem recuperação, `top(class)` → S e cascata.
- *Membro* (`parseClassOrMixinOrExtensionOrEnumMemberImpl`): `get`/`set` seguido de reservada +
  `indicatesMethodOrField` → recuperado (`:4609-4615`); identificador + reservada +
  `indicatesMethodOrField` sem tipo → recuperado (`:4743-4754`); nome que não é identificador →
  `recoverFromInvalidMember` (`:9325`): `class`/`enum`/`typedef` → `CLASS_IN_CLASS`/`ENUM_IN_CLASS`/
  `TYPEDEF_IN_CLASS`; operador → declaração de operador inválida; `( => {` ou acessor →
  `parseMethod`; sem nada lido → `EXPECTED_CLASS_MEMBER`; senão `parseFields` (o contexto decide).
- *Comando* (`parseExpressionStatementOrDeclarationAfterModifiers`, `:8115-8212`): `computeType(…,
  required: false)` devolve `noType` para `int class` (reservada não "parece nome") → comando de
  expressão `int`, `;` que falta relatado no `int`, e `class = 10;` é outro comando (K por expressão).
- *Parâmetro* (`:2023-2028`): `computeType` com `acceptKeywordForSimpleType`: `T palavra` seguido de
  `= : , ) ] }` é tipo + nome; o nome cai no contexto de parâmetro → K (`f(int class)`, `f(int void)`).
- *`break`/`continue`/rótulo*: sem identificador depois, o contexto não é chamado; `break class;` é
  `break` sem alvo (`;` relatado no `break`) seguido do comando `class;`.
